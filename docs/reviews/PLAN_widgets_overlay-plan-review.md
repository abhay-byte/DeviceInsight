#### [CRITICAL] Single-writer bus claim contradicts BUDGET cold-path sampler
- Location: docs/plans/PLAN_widgets_overlay.md:186-206, 258-267, 0.8 / Architecture Map:102-110, DashboardRepositoryImpl.kt:61-71 + 236-252, BenchModel.kt:256-377

That is a **second writer with different fidelity**, contradicting the single-writer invariant and causing foreground vs BUDGET widgets to render different fields (e.g., `cpuHist` size, `memComposition` detail).
- Evidence: `DashboardRepositoryImpl.kt:61` `while(true){ emit(collectMetrics()); delay(1000)}`; `DashboardRepositoryImpl.kt:242` `BenchSnapshotCache.last = metrics.toBenchSnapshot(...); BenchUpdater.nudge(context)`; `BenchModel.kt:256` `object BenchSampler { fun sample(context): BenchSnapshot { ... } }` with no history; `PLAN_widgets_overlay.md:203` `fun pushSlow(...)` and `265` `Do not spin the 1 Hz loop from WM`.
- Impact: Worker will implement bus correctly for foreground but BUDGET will silently diverge; tests extending `toBenchSnapshot` will not cover `BenchSampler` mapping (currentMa, batteryPresent, etc.); wasted impl if worker later discovers need to unify mappers.
- Required planner change: Explicitly redefine invariant: **Foreground: single writer = `DashboardRepositoryImpl` → `MonitorBus` → widgets/HUD**. **BUDGET (process dead): sampler = `BenchSampler.sample()` → direct `GlanceAppWidget.update()` with no bus publish; document that BUDGET snapshot is intentionally lossy and list its field limitations (e.g., histories empty, memComposition single segment). #### [CRITICAL] Memory composition parser math under-specified — fractions may exceed 1
- Location: docs/plans/PLAN_widgets_overlay.md:230-243, BenchModel.kt:195-207, MemoryProvider.kt:1-36, DashboardRepositoryImpl.kt:256-274

Worker copying the prose will produce hatch bar where `x+segW > w` (currently clamped by `coerceAtMost(w)` in `BenchArt.hatchBar`) but ZRAM+swap double counts and free may be negative.
- Evidence: `MemoryProvider.kt:12` only exposes `totalMem/availMem` via `ActivityManager`; `/proc/meminfo` not read today; `DashboardRepositoryImpl.kt:256` manual `SwapTotal`/`SwapFree` parsing but no Active/Cached; `BenchModel.kt:198` `usedFraction = ramUsedBytes.toFloat()/ramTotalBytes`; `0.4` prose lacks denominator.
- Impact: Visual bug — hatch bar segments sum >100% and overlap, or free negative; unit test `MemInfoParser fixture: Active/Cached/Zram/free fractions sum to ~1 ±0.05` will fail non-deterministically.
- Required planner change: Pin exact computation in `MemInfoParser.kt`: `parse(path: String, zramBytes: Long?): List<MemSeg>` reads `MemTotal`, `Active`, `Cached`, `SwapTotal`, `SwapFree`. Document order `active,cached,zram,swap,free` and that blueprint hatched bar uses same fractions.
